# algorithm-explainer

把算法题讲到你能自己拿笔算完 —— 一个给 AI agent 用的算法讲解 skill。

## 安装

把这段发给你正在用的 AI 助手：

```
把 https://github.com/heix0x/algorithm-explainer 装到你的 skills 目录，
读一下它的 SKILL.md，装好告诉我
```

不用配置，只有一个 `SKILL.md`，没有外部依赖。

<details>
<summary>手动装</summary>

```bash
git clone https://github.com/heix0x/algorithm-explainer.git ~/.workbuddy/skills/algorithm-explainer
```

其他客户端换成对应的 skills 目录即可。如果那儿已经有同名目录（比如之前建过目录联接），先把旧目录摘掉再克隆。
</details>

## 用法

装好之后直接说人话，不用记 `/` 命令：

| 你说 | 它做 |
|---|---|
| 「用大白话给我讲讲最大子段和」 | 按七步走：定锚点 → 小例子 → 比喻 → 逐步演示 → 公式 → 题眼 → 反例 |
| 「动态规划我听不懂，从零讲一遍」 | 先问你会什么、拿哪个当参照，找到锚点再开讲，不硬灌 |
| 「这道题我算错了，帮我看看错在哪」 | 定位到具体状态转移，指出错在哪一格，而不是重讲一遍 |
| 「KMP 到底在跳什么」 | 用一个 5 字符的串演示，画出 next 数组怎么变 |

只说「讲讲动态规划」这种没指定题目的，它会先问讲哪一道，不替你挑。

## 它解决什么

让 AI 讲算法，最常见的失败是这三种：

| 毛病 | 长什么样 | 后果 |
| :--- | :--- | :--- |
| **例子太大** | 上来就讲教材原题，7×6 的表、10 个元素的数组 | 第一步就淹死，后面全在硬撑 |
| **公式先行** | 先甩递推式，再解释每个符号 | 读者只能背，答不出"为什么是这样" |
| **只有文字** | 大段说"然后取最大值、再回溯"，表格堆在文末 | 看不到状态怎么变，等于没演示 |

这个 skill 把这三条写成**红线**，并规定一套七步流程。核心主张只有一句：

> **先让手能跟着做，再让脑子知道为什么，最后才给符号。**

## 七步流程

| 步 | 做什么 | 硬指标 |
| :--- | :--- | :--- |
| 0 · 定锚点 | 找出读者已经会的东西，做对照 | 必须落到"格子含义变了没有"这一条 |
| 1 · 例子定规模 | 选一个能一口气手算完的输入 | 元素数 ≤ 6，步骤 ≤ 12 |
| 2 · 造比喻 | 有动作、状态可数、写明失真点 | 三条缺一不可 |
| 3 · 逐步演示 | 每步一句推理 + 一张状态快照 | 未算的留 `·`，当前格加粗 |
| 4 · 公式回译 | 演示完才给公式 | 必须配"动作 ↔ 符号"对照表 |
| 5 · 题眼 | 一句话说穿"为什么不是别的可能" | 全文只准有一个 |
| 6 · 反例 | 给一个按直觉算就会错的输入 | 指出错在哪一步 |
| 7 · 门槛测试 | 给一个没出现过的新输入 | 只给答案，不给过程 |

## 四条红线

1. **第一个例子元素数 ≤ 6**，手算步骤 ≤ 12。教材原题几乎总是太大，不能直接拿来当入门例子。
2. **公式必须在演示之后**。先给公式再解释，等于让读者背结论。
3. **不能连续两步没有状态可见**。每步都要有表、图或数组快照。
4. **主线 ≤ 150 行，其余进附录**。一篇写到底的讲解，读者会在第 100 行之后掉队。

## 适用边界

这套方法对"步骤可枚举"的算法最强，其它类型要换演示载体，不能硬套。

| 类型 | 适配度 | 调整 |
| :--- | :--- | :--- |
| 填表型 DP、递推、贪心、模拟、枚举 | 强 | 直接照七步走 |
| 图算法（最短路、最小生成树、拓扑排序） | 中 | 比喻换"地图/邮差路线"，状态用"已确定的点集"，图代替表 |
| 树、递归、分治 | 中 | 比喻换"分包裹/拆任务"，演示换成画递归树 |
| 数据结构（堆、并查集、跳表） | 弱 | 演示换成"插入一个元素后的结构图" |
| 纯数学证明、复杂度推导 | 不适用 | 改用"证明骨架 + 关键引理 + 反例" |

遇到不适配的，先说明这套讲法在这里不适用，再给替代路径 —— **硬造的比喻比没有比喻更糟**。

## 输出长什么样

```markdown
# <算法名>：<一句话比喻>

## 一、这题在问什么      ← 定义 + 与已会知识的差异对照表
## 二、画面：<比喻>      ← 规则 ≤ 3 条 + 失真点一句
## 三、一格/一步 = 什么   ← 状态定义，全文最容易错的地方
## 四、走一遍            ← 逐步 + 状态快照
## 五、公式              ← 动作 → 符号 对照表
## 六、题眼              ← 一句话
## 七、反例              ← 会算错的输入
## 八、自测              ← 2～3 题，含一个新输入
## 附录（可选）          ← 复杂度、代码、边界讨论
```
